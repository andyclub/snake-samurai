# Repository instructions

## Git delivery policy (no pull requests)

- Do not create, request, approve, or merge a pull request for this repository unless the owner explicitly makes an exception for the task. Integrate validated changes into the existing default branch with a normal fast-forward push. If existing instructions call for a working branch, keep that isolation until validation is complete.
- Keep all existing required tests, build checks, security controls, approvals, and deployment procedures. A push is not proof of a production release; verify the deployed revision when releasing. If existing protections block a direct push, report the blocker without bypassing or weakening them. Never force-push.
